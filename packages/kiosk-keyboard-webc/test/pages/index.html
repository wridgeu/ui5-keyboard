Auto-Type Detection: ui5-step-input

The auto-type detector checks the resolved native <input> for type="number" or inputmode="numeric". However, ui5-step-input renders its inner input as type="text" without an inputmode attribute, so auto-detection sees no numeric signal and falls back to Full (QWERTY). The data-keyboard-type="Numpad" attribute provides a framework-agnostic override that crosses shadow DOM boundaries.

Age - no override Inner input has type="text", auto-type resolves to Full (QWERTY).
Age - with data-keyboard-type Override attribute found via shadow DOM traversal, auto-type resolves to Numpad.

Custom Composition Middleware (instanceMiddleware)

A per-instance emoji-compose layout bound to a custom CompositionMiddleware: type : then ) → 🙂, : ( → 🙁, : D → 😄, ; ) → 😉.

Per-Instance Locale Layouts (instanceLocaleLayouts)

With no layout attribute, the keyboard derives its default from the browser locale. instanceLocaleLayouts overrides that mapping per instance.

i18n Resolver (accessibility labels)

Demonstrates KioskKeyboard.setI18nResolver(). The resolver overrides ARIA labels and screen reader announcements (e.g. "Virtual keyboard opened", "Caps Lock on") as well as the visible text of built-in special keys (Shift, Enter, Backspace, Space). Layout-defined labels such as "123" or "かな" are not affected by the resolver. Select a language and inspect the changes below.
